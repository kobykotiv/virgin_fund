## Brief overview
  - Guidelines for appending summaries to code/documentation changes and for structuring progress reports in the "virgin_fund" project.

## Code and documentation change summaries
  - After every code or documentation change, append a concise summary labeled **Summary of Changes** at the end of each code block.
  - Summaries must be clear, relevant, and easy to review.

## Progress report summary requirements
  - At the top of each progress report (every 6th iteration or as requested), include a **Summary of Next Planned Change** section outlining the next intended update or feature.
  - Follow with the standard progress report sections as defined in progress-reporting.md.
  - If the user requests a different summary format or cadence, follow the user’s instruction.

## Content guidelines
  - Ensure all summaries are concise, relevant, and formatted for easy review.
  - Always keep summaries aligned with the current project scope and user priorities.
