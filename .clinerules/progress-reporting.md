## Brief overview
  - Guidelines for providing regular, concise progress reports during development of the "virgin_fund" trading platform.

## Progress report cadence
  - After every 6th user prompt or major development iteration, provide a progress report.
  - If the user requests a report sooner or later, follow the user's instruction.

## Progress report format
  - Clearly label the report as a "Progress Report".
  - Include the following sections:
    - **Summary of completed tasks:** List features, fixes, or changes made since the last report.
    - **Current status:** Briefly describe the current state of the app or module.
    - **Outstanding tasks:** List remaining or upcoming tasks, features, or known issues.
    - **Blockers or questions:** Note any issues needing clarification or user input.

## Content guidelines
  - Keep the report concise and relevant to the current project scope.
  - Ensure the report is up to date and easy to review.
  - Always keep the progress report aligned with the current project scope and user priorities.
